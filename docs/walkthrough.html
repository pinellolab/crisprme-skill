What happens when someone uses the CRISPRme skill

The skill lets someone install and run CRISPRme+ v2.7.9 by asking in plain language. Each scenario below shows what the person asks, what Claude answers, and the commands Claude runs in the background. Click any background step to see what happened.

Unless a card says otherwise, the command output is real, captured from test runs on the lab server on 2026-10-13, with long paths shortened. The conversation wording is written for illustration.

Before a search

Working out what a search actually needs

complete-search has around 20 options, but only a few deserve a question. The skill sorts them into tiers.

TierWhat Claude doesOptions
Always askNo sensible default existsguide sequences, genome build
Default, and say soStates the assumption so the user can change itdepth (4 mismatches, 1 DNA + 1 RNA bulge), PAM (SpCas9 NRG), job name
Quick checkChanges what gets searched, so worth a yes or novariant-aware or not, which panel, population-level or per-person, annotations
Leave aloneOnly raised if the user raises itthreads, merge window, sorting, base editing, GPU
You
Can you check my guide CTAACAGTTGCTTTTATCAC for off-targets?
Claude

Yes. Here is what I plan to do, so you can correct anything:

  • hg38, SpCas9 with the NRG PAM (NGG plus NAG), the guide padded to CTAACAGTTGCTTTTATCACNNN.
  • The recommended depth: up to 4 mismatches plus 1 DNA and 1 RNA bulge. Say if you want deeper or shallower.
  • Functional annotation included: regulatory elements, nearest gene, cancer-driver genes.

Two questions. Should this be variant-aware, meaning it searches the genomes of the 4,091 people in the HGDP and 1000 Genomes panel rather than the reference alone? That is CRISPRme's main advantage. If so, is a population-level screen enough, or do you need the named individuals who carry each off-target?

You
Yes, variant-aware. Population-level is fine for now.
Deeper searches get a cost check first. Before launching 6 mismatches with 2 and 2 bulges, Claude runs CRISPRme's own estimator; that setting comes back EXTREME, around 200 GB of intermediate files with a risk of running out of memory, and Claude says so before starting. COSMIC cancer annotations stay off unless the user confirms they hold a COSMIC licence; Claude never enables them on its own.

When an input is wrong

Failing in seconds instead of hours

CRISPRme checks its inputs before the pipeline starts. That changes what a fast failure means: read the report first, rather than assuming a deeper problem.

You
Run my SaCas9 guide GCAGCATCCTCTAGAGGATG against the HGDP panel.
background · seconds later, already FAILED scripts/check_run_status.sh sacas9-1013 
$ scripts/check_run_status.sh sacas9-1013
status: FAILED
process: not running
--- last 15 lines of log ---
  [OK] Guide file: guides.txt
  [ERROR] guides.txt: guide 'GCAGCATCCTCTAGAGGATGNNNNNN' is 26 nt but the PAM
  '21bp-NNGRRT-SaCas9.txt' expects a padded length of 27 nt (protospacer + 6 nt PAM).
Result: FAILED (1 error) - aborting before launching complete-search
Claude

Stopped in seconds rather than hours failed. Nothing ran, so there is nothing to clean up.

The length does not match: this SaCas9 PAM file expects a 21-nucleotide spacer plus a 6-nucleotide PAM, and the guide you gave me has a 20-nucleotide spacer. CRISPRme suggests adding more N characters, but that would be wrong here, because the spacer itself is one base short. Can you confirm the full 21-nucleotide spacer, or should I use the 20-mer SpCas9 PAM instead?

Two tiers run here. A quick one always checks genome, PAM, guide and sample files, and since 2.7 it treats a sample that is missing from the panel as an error. A slower, opt-in pass reads every record of a new VCF, which matters when someone brings their own cohort data.
Which people carry it

Per-person results and a single individual's card

By default CRISPRme+ reports one worst-case representative per site. Asking about named individuals switches the analysis mode.

You
Which individuals in the panel actually carry these off-targets?
Claude

That needs a different mode. The run we did was population-level, which is lossless for finding sites but reports worst-case representatives rather than people. The per-person mode resolves each individual's actual pair of chromosomes, so you get named carriers, confirmed pairs of variants that sit together on one chromosome copy, and exact joint frequencies. Shall I re-run that way on the same guide?

A different nuclease

SaCas9 against the same population panel

The downloadable indexes are all SpCas9. Any other nuclease needs its own index, but not a rebuild of the variant data: upstream publishes the variant-enriched genome separately, so only the nuclease-specific part is built.

You
I need to screen a SaCas9 guide against the same HGDP panel. Is that possible?
Claude

Yes, and it does not mean rebuilding the population data. I download the prepared variant-enriched genome for that panel, about 1 GB, and build just the SaCas9 index from it. That takes roughly 10 minutes here, plus the search itself.

One thing to know up front: both of CRISPRme's activity scores are trained on SpCas9, so SaCas9 sites get no score. The results are ranked by mismatches and bulges instead.

A personal genome assembly

Searching someone's own assembled genome

When an individual's genome has been assembled rather than genotyped, there is no need to infer their variants: each of the two assembled copies is their actual sequence. CRISPRme searches both and then lines the results up against the reference.

You
We have HG01255's assembly from HPRC, both copies. Can you search it directly?

$ scripts/run_crisprme_job.sh assembly-search hg01255-sg1617 \
    --assembly-individual HG01255 \

# two full searches back to back, then reconciliation; budget several hours

Started. This runs a complete search on each of the two copies, then matches the predictions against each other and against hg38, so plan for well over double a single search. No variant panel is involved here, so there is nothing to choose on that front.

Cross-checking

Is CRISPRme itself finding everything?

A separate check compares CRISPRme's results against an exhaustive search of the same region, so it tests correctness rather than just whether the run completed.

What the skill handles

  • Install and data setup. Checks for existing installs first, then sets up the official v2.7.9 container on Apptainer, Docker or a source install, and downloads the reference data and variant panel as background jobs.
  • Plain-language searches. Asks only about the choices that matter, states its assumptions for the rest, and estimates the cost before anything expensive.
  • Trustworthy job status. Nothing blocks the conversation, and the status check catches the cases where CRISPRme reports success without having done the work.
  • Results in words. Points at CRISPRme's own shareable report and gives a terminal summary: how many sites exist only because of population variants, whether the on-target is unambiguous, which populations carry the most risk, and a ready-made validation panel.
  • Per-person answers. Switches to per-individual mode when the question is who carries a site, and builds a card for one named individual.
  • Beyond the defaults. Other nucleases, non-human genomes and a user's own cohort data, each with the real time and disk cost stated up front.
  • Personal assemblies. Searches both copies of an assembled genome and surfaces the sites no reference-based search can see.
  • Correctness checking. Compares CRISPRme's output against an exhaustive search on a test region.
